# NT Studio — بيئة عمل شخصية لنموذج ذكاء اصطناعي (Windows)

تطبيق سطح مكتب يمنح نموذجك المتّصل بيئة عمل كاملة على جهازك: ملفات وأوامر وبحث وويب ومعاينة حيّة، وتحكّم كامل بالكمبيوتر بدقة 1:1.

**المبدأ:** النموذج هو المتحكّم والمقرّر، والتطبيق هو البيئة. لا أوامر سلوكية مفروضة، ولا قيود على ما يفعله — فقط **دليل تعريفي** بالأدوات، وشبكة أدوات احترافية، وواجهة تُظهر كل شيء بوضوح.

> ⚠️ **العقد الملزِم:** قبل أي تعديل على هذا المشروع اقرأ [`AGENTS.md`](./AGENTS.md) — فيه الفكرة الأساسية، والشروط الثمانية غير القابلة للتفاوض، وبروتوكول العمل، وقائمة الممنوعات.

---

## المتطلبات

- Windows 10/11 مع **Node.js 22 أو أحدث** (`winget install OpenJS.NodeJS.LTS`).
- (اختياري) **Visual Studio Build Tools** مع «Desktop development with C++» لبناء `better-sqlite3` و`node-pty`.
  إن تعذّر البناء، يعمل التطبيق بلا مشكلة: يعود تلقائياً إلى ملف JSON بدل SQLite، وإلى `child_process` بدل `node-pty`.

## التشغيل

```powershell
npm install        # يثبّت الاعتماديات ويعيد بناء الوحدات الأصلية لإصدار Electron
npm run dev        # تشغيل للتطوير
npm run typecheck  # فحص الأنواع
npm test           # كل الاختبارات
npm run build      # بناء الإنتاج إلى out/
npm run dist       # مثبّت .exe في release/
npm run run:latest # يبني نسخة معزولة ويشغّلها (Run-Latest.ps1)
```

## أول تشغيل

شاشة المزوّد: الاسم، Base URL، مفتاح الـ API، نوع الواجهة (متوافقة مع OpenAI / مع Anthropic / OpenAI Responses)، والنماذج — زر «جلب القائمة تلقائياً» يستدعي `/models`. عند «حفظ والبدء» يُحفظ المزوّد فوراً (المفتاح مشفّر عبر `safeStorage`) ويُختبر الاتصال في الخلفية؛ إن فشل يظهر تنبيه فقط.

لكل نموذج قابل للتعديل: يدعم الأدوات؟ يدعم الصور؟ حجم السياق؟ أقصى إخراج؟

**الإعدادات الجاهزة:** OpenCode Go (٢٩ نموذجاً معرّفاً مسبقاً) · Anthropic · OpenAI · OpenRouter · DeepSeek · Google Gemini · Ollama محلي.

## وضعان في شريط علوي واحد

| الوضع | ماذا يفعل |
|---|---|
| **Studio** | برمجة وبناء مشاريع: ملفات، أوامر، معاينة حيّة داخل التطبيق، كود، طرفية، سجل أدوات. |
| **Agent** | تحكّم كامل بالكمبيوتر: يرى الشاشة 1:1 مع تقاطع مؤشر ومسطرة، يحرّك الماوس والكيبورد فعلياً عبر Win32، يفحص عناصر الواجهة بـ UIA، ويصغّر التطبيق إلى شريط عائم للعمل أمام عينك. |

المبدّل في أعلى النافذة، ولكل وضع جلساته الخاصة.

## زر `+` في صندوق الكتابة

ضغطه يفتح قائمة صغيرة فيها أربعة إجراءات:

1. **إضافة صورة** — أو الصق مباشرة بـ `Ctrl+V`.
2. **إضافة ملف** — نافذة اختيار نظامية، دعم عدة ملفات، ومعاينة نصية تُمرَّر مع المسار للنموذج.
3. **إضافة مجلد** — يُمرَّر مسار المجلد ومحتواه فيُوجَّه النموذج للعمل عليه مباشرة.
4. **استخدام مهارة** — قائمة فورية لكل المهارات، وفي مقدمتها **«صانع المهارات الاحترافية»**.

المرفقات تظهر كشرائح قابلة للإزالة فوق الصندوق، وتُدمج في نص الرسالة.

## المهارات (Skills)

مكتبة Markdown قابلة للتحرير بالكامل داخل `%APPDATA%\NT Studio\skills`. كل ملف مهارة:

```markdown
# اسم المهارة
> وصف سطر واحد يظهر في الفهرس

المحتوى التفصيلي: الهدف، المكدس والأدوات، خطوات التنفيذ، معايير الجودة.
```

- تُزرع عند أول تشغيل: «صانع المهارات الاحترافية» + «صفحة هبوط عربية» + «لوحة تحكم تفاعلية» + «لعبة Canvas» + «واجهة خلفية Node» + «أتمتة Python».
- تُدار من **الإعدادات ← تبويب «المهارات»**: إنشاء، تعديل، حذف، وتفعيل مباشر في صندوق الكتابة.
- **الوكيل نفسه ينشئ مهارات** عبر `skill_save` — يكتب المهارة ثم تحفظ في التطبيق فوراً.

## تخصيص برومنت الوكلاء

**الإعدادات ← تبويب «برومنت الوكلاء»**:

- **برومنت الوكيل الباني والمعدّل (Studio)** — يُستبدل بالدليل الافتراضي بالكامل إن كتبت نصاً. زر «تعبئة الافتراضي للتعديل» لتحميل النص الحالي للتعديل عليه، وزر «استعادة الافتراضي» للرجوع.
- **برومنت الوكيل المتحكّم بالكمبيوتر (Computer)** — نفس المنطق لوضع Agent.
- **التوجيه الشخصي (Persona)** — يُلحق بذيل تعليمات النظام في الوضعين.

أي نص تكتبه هنا يبقى في موضعه الثابت (الذيل) فلا ينكسر الـ prompt cache.

## وضعان للصلاحيات

للتطبيق وضعان تختارهما من قائمة بجانب منتقي النموذج في الشات، أو من **الإعدادات ← البيئة والحدود**:

- **الأدوات الافتراضية** (`ask`، وهو الافتراضي): القراءة والبحث وكتابة الملفات الجديدة وتحكّم الشاشة والماوس تُنفَّذ تلقائياً، أما الإجراء الخطر — حذف ملف أو مجلد، استبدال ملف موجود، أمر نظام (حذف/تهيئة/إيقاف تشغيل/خدمات/ريجستري/إقلاع)، قراءة أو رفع ملف حساس (`.env`، `id_rsa`، `.pem`، `.key`، `.pfx`، كلمات السر)، النشر العام، أو الرفع إلى موقع خارجي — فيُعرض عليك في حوار يسمّي الأداة والهدف والسبب. إن رفضت، لا يُنفَّذ الإجراء ويصل النموذجَ رفضك فيكمل بخطة أخرى. الحوار بلا مهلة: ينتظرك مهما طال، ويُرفض تلقائياً إن أوقفت الجلسة.
- **الوصول الكامل** (`full`): ينفّذ كل شيء مباشرة بلا أي سؤال — السلوك الأصلي للتطبيق حرفياً. يُعرض تحذير مرة واحدة عند أول تفعيل.

لا حارس مسار ولا حارس أمر داخل الأدوات: الفحص كله في نقطة واحدة (`src/main/tools/permission.ts`) ويقفز عليه الوضع `full` بالكامل. التطبيق يعمل بصلاحيات المستخدم (`requestedExecutionLevel: asInvoker`)، وكل شيء على الجهاز متاح للنموذج.

## البنية

```
src/shared       الأنواع والعقود المشتركة + كتالوج OpenCode Go + حساب الديف
src/preload      جسر contextBridge (العقد الوحيد بين الواجهة والعملية)
src/main
  agent/         الحلقة ReAct، الدليل التعريفي، السياق والذاكرة، المهارات
  providers/     بوابة LLM واحدة: OpenAI + Anthropic + Responses (بثّ) + وضع XML البديل
  tools/         كل الأدوات (Tool[] بمخطط JSON صارم)
  desktop/       التحكم بالكمبيوتر: منطق + عامل Win32/C# + هندسة 1:1 + بصمة بصرية
  preview.ts     المعاينة الحيّة (WebContentsView) وحدودها وسجلاتها
  workspace/     المشاريع وGit ونقاط الاسترجاع وخريطة المشروع
  store/         SQLite (مع بديل JSON) والمزوّدون والمفاتيح المشفّرة
src/renderer     الواجهة فقط (React + Tailwind + Zustand) بنظام تصميم Graphite Studio
tests/           اختبارات node:test على الكود الحقيقي
scripts/         seed-memory.mjs · verify-agent-fixes.mjs
```

## أين تُحفظ البيانات

| ما | أين |
|---|---|
| قاعدة البيانات (جلسات، مزوّدون، ذاكرة دائمة) | `%APPDATA%\NT Studio\nt-studio.db` (أو `.json` كبديل) |
| المهارات | `%APPDATA%\NT Studio\skills` |
| السجلات (دوّارة) | `%APPDATA%\NT Studio\logs` |
| المشاريع | المجلد المختار في الإعدادات (افتراضياً `~\nt`) |

مفاتيح المزوّدين مشفّرة عبر `safeStorage`، وتُحجب تلقائياً من كل سطر سجل.

## ما يخزّنه كل مشروع

`.agent/PROJECT.md` (الوصف والقرارات وهوية التصميم) · `.agent/TODO.md` (الخطة) · `.agent/memory.json` (حقائق) · `.agent/log.jsonl` (سجل الأدوات).
يُنشأ Git نقطة استرجاع بعد كل مرحلة منجزة، وزر «تراجع» في درج المشاريع يعيد آخر نقطة.
